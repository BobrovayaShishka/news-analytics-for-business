Верни только JSON реестра утверждений.

Слои:
- fact: только то, что есть в факте, ссылка fact:*
- alfa: только пересказ карточки Альфа-Банка с датой, ссылка card:*
- model: вывод по признаку клиента или механизму, без атрибуции банку
- hypothesis: предположение, формулировка через «платёжная связь», без «поставщик» и «покупатель»

Вывод — не пересказ fact/title. Слой model отвечает на вопрос «что это значит для компании»:
связка событие → признаки/механизм → следствие для профиля. Перефразировать заголовок
или факт в why_it_matters нельзя.

В context pack смотри секции:
- «Факторы для интерпретации» — mechanism + feature + reason + missing_critical;
- «Клиентские последствия (черновик кода)» — шаблонные risks/opportunities/scenarios;
  опирайся на них, уточняй и расширяй, не подменяй пересказом новости;
- «Уже известные риски/возможности из новости» — только evidence, не готовый ответ клиенту;
- «Запрет» — не копировать title/summary в model-claims без нового смысла;
- «Конкурирующие сигналы» (если есть) — банк vs новость / echo: риски vs возможности, не усреднять.

В why_it_matters — минимум 2 независимых фактора, если они есть в context pack.
Фактор: сработавший механизм, карточка банка, calc, смежная новость, stats, группа/граф.
Каждый фактор — отдельное утверждение (model или alfa) со своими ссылками.
Если доступен только один фактор — так и пиши; не выдумывай второй.

Запрет однофакторного «очевидного» вывода, если сработали ≥2 механизма или в пакете
есть bank card / calc: нельзя сводить всё к одной фразе. Покрой независимые контуры.

Обязательные блоки последствий → риски → возможности. Формулируй через профиль
(признаки, механизмы, critical fields вроде «если ставка плавающая… / если доля FX mid…»,
calc-масштаб, группа/граф), а не только цитаты из новости.
Карточки alfa / смежные новости / stats — усиление или смягчение (риск vs возможность).
Extraction risks/opportunities — только evidence в assumptions, не единственный ответ.
Если при сработавших механизмах отдельного риска/возможности нет — явный
«нейтральный эффект при текущих признаках», а не «в тексте не названы».

Сценарии: 2–3 ветки с разной логикой (базовый / негативный / условный) и разными
support_refs. Не одна заглушка «условный масштаб». Правдоподобность: low, medium или high.
Без вероятностей.

impact_rationale — содержательное обоснование последствий, согласованное с рубрикой
(определение уровня в пакете). Уровень влияния по-прежнему ставит код: не спорь с ним
и не подменяй его текстом.

Не выдумывай числа. Каждое число ссылается на fact, card или calc.
Не утверждай тип ставки, сумму долга и валютную долю, если их нет в user_provided.
